# AGENTS.md — заметки по проекту X96S (читать первым!)

Рабочая папка `D:\x96s`, пользователь говорит по-русски — отвечай
по-русски, КОРОТКО (длинные ответы забивают контекст и всё тормозит), при условии что явное требование юзера что то объяснить отсутствует.

## Правило №0
Перед ЛЮБОЙ работой прочитай `README.md` (хаб) + ВСЕ файлы в `docs/`
ЦЕЛИКОМ, от начала до конца.
Они — истина в последней инстанции (`docs/6-pitfalls-status.md` = текущее
состояние, там же сырая история доводки, обновляй их после каждого шага).
Этот файл — только шпаргалка, а не замена.

## Железо (не выяснять заново)
- Стик X96S 2/16: Amlogic S905Y2, WiFi RTL8723BS (ТОЛЬКО 2.4GHz, SDIO
  `024c:b723`), ИК `meson-remote ff808040.rc`, USB-A только USB 2.0.
- UART УБИТ: криворукий юзер оторвал пятак TX с корнем и снёс
  2 резистора у RX/TX, схемы на плату нет. Так что про UART
  и консоль u-boot можешь забыть. UART-логи когда то удачно снимались (с помощью ESP32 C3 super mini и скетчем на несколько строк кода) но теперь возможности их снять не будет.
- Кнопка reset НИЧЕГО НЕ ДЕЛАЕТ (всегда грузится сразу в ОС,
  рекавери через неё не вызывается, как минимум при кастомном загрузчике от LineageOS radxa0/_tab). Не предлагать.
- Тестпоинт eMMC существует (рядом с чипом Samsung, фото с 4pda
  совпало) — maskrom пинцетом + USB Burning Tool это путь
  раскирпичивания.
- Сток = `X96S_P_20200903-1822.img`, кастом = `sbx_*atv*.img`
  (slimBOXtv, НЕ сток). Не путать.

## Тайминги и adb
- После перезагрузки в Андроид жди 50-55 секунд перед adb (30 мало).
  Перезагрузка в рекавери/sideload/fastboot — быстрее, хватает
  20 секунд.
- `adb root` слетает после каждой перезагрузки; в свежем рекавери
  adb надо включать пунктом меню вручную, то есть просить юзера (иначе пусто/unauthorized).
  После `adb root` ждать НЕ надо (эффект мгновенный, никаких
  `Start-Sleep` после него).
- `adb shell` портит БИНАРНЫЙ вывод (CRLF) — для бинарников только
  `adb exec-out` (например `/proc/config.gz`).

## Правила шелла (Windows PowerShell!)
- НЕТ `grep|head|tail|sed|awk|strings` — их не существует. Используй
  специальные инструменты (Grep/Read/Edit/Write) или `python -c` /
  `Select-Object`.
- adb это `.\adb.exe` с workdir
  `C:\Users\user\Downloads\platform-tools`.
- ssh `ubuntu-vm` (по ключу) — это Linux-окружение (VirtualBox,
  Ubuntu 26.04.1 LTS). Осторожно с кавычками: PowerShell съедает `\"` и `$var`
  внутри ssh-команд — скрипты лучше писать через Write+scp, а не
  инлайн-heredoc.
- Общая папка с виндой: `D:\x96s` на VM видна как `/media/sf_x96s`
  (vboxsf, юзер уже в группе). Через неё закидываем на VM прошивки
  и забираем готовые `out/*-x96s-fix.zip`; сам патчер работает
  локально на VM, без ssh.
- Стенд (лично юзера, в README не тащить): хост VirtualBox 7.2.20 +
  Guest Additions 7.2.20 с ISO хоста (репо-пакеты 7.2.6 снесены: нет
  Wayland-буфера + `vboxsf: Unknown parameter 'tag'`). Юзер в группе
  `vboxsf` (иначе ни буфер, ни общая папка), `/dev/vboxguest`
  root:vboxsf. Общая папка `x96s` (D:\x96s) автомонтится
  в `/media/sf_x96s`.
- ssh из скриптов: только `ssh -o BatchMode=yes -o ConnectTimeout=15`
  (иначе висит на парольном промпте при выключенной VM).
  VM иногда сама ребутнулась (аптайм 4 мин = только что) — не пугаться.
- WSL НЕ установлен. Нет `dtc`/линуксового тулчейна на Windows.
- `ampack` (распаковка Amlogic .img в .PARTITION, ставился через
  `cargo install ampack`, нужен ещё git) сейчас в системе НЕ установлен
  (в прошлый раз использовался разово для `sbx_unpack/`) — ставить
  заново по требованию. Не путать с `rockchip_wlan` (это исходники
  WiFi-драйвера с GitHub, не cargo).

## Правила сборки (выучены кровью)
- Ядро: `LineageOS/android_kernel_amlogic_linux-4.9`, ветка
  `lineage-22.2`, конфиг ТОЛЬКО с живого `/proc/config.gz`
  (распаковать!). Драйвер: `youling257/rockchip_wlan`, подкаталог
  `rtl8723bs`, v5.2.17.1.
- Стоковый 8723bs.ko 32-битный (ядро aarch64) — бесполезен, не пробовать.
  `MODULE_FORCE_LOAD` выключен — чужой .ko не встанет никогда.
- НИКОГДА не `strip` модули ядра (ломает ELF для загрузчика 4.9:
  `Module len truncated`).
- Патчи исходников — файлами в `patches-rtl8723bs/` (WiFi) и
  `patches-uboot/` (загрузчик), применяются скриптом
  `apply_patches.py <target>` (проверен побайтово со старым деревом).
  Драйверу нужны `extern_wifi_set_enable` + `sdio_reinit()`.
- Тяжёлые сборки: длинные компиляции пользователь гоняет САМ у себя
  в терминале, когда попросишь (или явно делегирует). Лог в файл,
  показывай только хвост.

## Правила прошивки (кирпич уже был однажды!)
- Патчер запускается НА `ubuntu-vm` (чистый Linux-скрипт, никакого ssh
  внутри): один аргумент — либо ПОР, либо ПОА (тип определяется сам):
  `cd /media/sf_x96s && python3 fix_x96s.py flash/los-*/lineage-*.zip`
  -> `out/<name>-x96s-fix.zip`, `python3 fix_x96s.py
  flash/los-*/aml_install_package.img` ->
  `out/aml_install_package-radxa0[_tab]-x96s-fix.img` (девайс-суффикс,
  иначе TV/TAB затрут друг друга). В самом начале проверяет
  `debugfs/e2fsck/python3-brotli` (`sudo apt install e2fsprogs
  python3-brotli`). Payload `8723bs-4.9.337.ko` рядом с CWD.
  `--skip a,b`, `--list` (там же targets ota/aip).
- Файлы внутри vendor-образов меняются настоящим ext4-драйвером
  (debugfs: rm/write/sif/ea_set, режимы и xattrs сохраняются),
  transfer.list перегенерируется полным `new`-покрытием
  (по размеру ФАЙЛА — в образах есть паддинг за концом ФС!).
  updater-script не трогается. Идемпотентность = побайтовое равенство
  (новый payload сам перепатчится).
- Подводные debugfs, уже учтены в скрипте: `write` даёт 0770
  (чинить через `sif ... mode 0100644`), `chmod`/`chown` ОТСУТСТВУЮТ,
  xattrs (`security.selinux`!) снимать `ea_get -f` ДО `rm` и
  возвращать `ea_set -f` после, `sif` пишет сырое значение (биты типа
  добавлять руками), выход debugfs проверять по тексту (код 0 врёт).
- В рекавери /vendor ТОЛЬКО ЧТЕНИЕ — sideload-зипы с копированием
  файлов НЕ РАБОТАЮТ. Только прошивка целых образов
  (block_image_update) или живой adb.
- Sideload-норма: `Total xfer: 0.97x` и застывшие `~45%` в конце —
  это штатно, не обрыв. Рецепт: `adb reboot sideload`, sleep 20,
  `adb sideload архив` (всё сам, юзера не дёргать). После этого девайс пропадает из `adb devices`
  (ставит/ребутится), дальше юзер сам выбирает в рекавери пункт про загрузку в систему. Можно ждать загрузку как обычно.
- После вайпа `/data` первая загрузка — всего ~1м50с (замерено
  таймером), не 15 минут. Дальше как обычно. Не пробуй сразу после вайпа стучаться в adb. Юзеру нужно вручную включать отладку. Включит - скажет.
- Overlayfs от `adb remount` применяется СЛИШКОМ ПОЗДНО для
  `on boot` insmod.
- ОБЯЗАТЕЛЬНО перед ЛЮБОЙ прошивкой: loop-mount пропатченных образов
  самим ядром 4.9 (`mount -o loop` на живом стике) + `insmod`
  с loop-mount. Монт на VM/новом ядре НЕ ДОКАЗЫВАЕТ ничего.
- Ограничения ext4-хирургии: тот же размер образа, плотные экстенты
  (без дыр — ядро читает нули!), GDT/битмапы НЕ ТРОГАТЬ (там
  checksum'ы!), e2fsck должен показывать только безвредные leak.
- Путь `dhd.ko` теперь содержит драйвер 8723bs (имя врёт, так задумано).
  Файлы прошивок НЕ нужны (firmware встроен в драйвер).

## Доки
- `README.md` — хаб-оглавление, истина — `docs/` (`6-pitfalls-status.md` = текущее состояние, обновляй).
  Никаких SSID/паролей в доках (поедет на GitHub) — и вообще
  никаких per-unit данных: серийники, MAC, CID eMMC, локальные IP
  маскируются (`XX:XX:XX`, `<из DHCP>`).
- Патчер модульный: `fix_x96s.py` — обёртка, логика в `x96s_patcher/`
  (по файлу на фикс в `fixes/` + `@register("имя", "описание", targets)`,
  порядок = порядок импортов; `amlogic.py` — свой парсер burn-пакетов).
   Новый фикс = новый файл + строка импорта, см. `docs/3-patcher.md`.
   Burn-пакету vendor/system не положены физически (логические разделы
   в super, пруфы в `docs/3-patcher.md` + `docs/5-bootloader.md`) — не пытаться их туда вшивать.

## Про пользователя (как с ним работать)
- Лёгких путей не ищет — только самые правильные и стабильные.
  Привередливый, костыли чует за версту. Не предлагай первым
  делом слипы, поллинг и «давай пока так, а потом разберёмся» —
  начни с событийного/детерминированного решения; поллинг только
  если докажешь, что иначе никак.
- Никаких fallback-слоёв «на всякий случай» без спроса — хочет
  одну чистую реализацию, а не три пути с флажками.
- Допрос — норма: будет вытягивать обоснование клещами, путать
  в показаниях не даст. Не знаешь — так и скажи + предложи
  решающий эксперимент (уважает честное «проверю» больше, чем
  уверенное гадание — проверено на истории со стоковым rc).
- Замеряет секундомером и ловит на расхождениях слов с делом
  (его замеры — истина, твои оценки — нет). Цифры в доки —
  только замеренные.
- Рубит зависшие команды без предупреждения: долгие операции
  режь на куски, вешай таймауты везде (`logcat` только с `-t`,
  ssh только с `BatchMode+ConnectTimeout`), иначе оборвёт
  посередине и будешь гадать, что успело выполниться.
- Может оборвать команду на полуслове, чтобы что-то сказать, —
  это не ошибка, а сообщение: остановись и спроси, что случилось.
- Говорит короткими командами («продолжай», «чекай логи», «шей») —
  это значит «делай стандартный drill, не переспрашивай». Стандарт
  после прошивки/бута: uptime, IP, dmesg (DOWN/UP + reinit + ndev
  с efuse-MAC), счётчик `-84`, ноль HAL-ошибок, пинг до AP без потерь.
- Прошивает то сам, то просит тебя (`adb reboot sideload`, sleep 20,
  `adb sideload`). Не гадай — уточни одной строкой, кто шьёт.
- При питании от USB ноута иногда замечались ребуты стика.
  Диалог fingerprint'а жмёт сам пультом на экране ТВ — просто жди.
