# Светодиоды: синий (работает) и красный (standby)

У стика два диода. Синий заведён стоковой логикой через DTBO-оверлей
(закрыто 2026-10-08, подтверждено глазами живьём). Красный из Linux
недостижим — это standby-диод на цепи AOCPU (доказано живьём там же).

## Синий: стоковая логика и перенос

Симптом: при включении синий тлеет, на стоке с началом загрузки
светится ярко; на LOS 22.2 тлел всегда.

Разведка по burn-пакету `X96S_P_20200903-1822.img` (парсер
`x96s_patcher.amlogic` + `fdtdump` + loop-mount vendor на VM):
вся стоковая логика — одна DT-нода `gpioleds` (`status okay`,
`sys_led`: periphs-банк `banks@ff6346c0` пин 64, active-high,
`default-state on`). Драйвер `leds-gpio` поднимает пин при старте
ядра — отсюда яркость. Он же есть в LOS (`CONFIG_LEDS_GPIO=y`).
Userspace в стоке мёртвый: `init.amlogic.board.rc` chmod'ит
несуществующие на этой плате `net_green`/`net_red` и `led_gpio`,
а Light HAL 2.0-passthrough везёт legacy-библиотеку… ни одной
(в `lib/hw` её нет), power HAL LED не трогает.

Диагноз LOS: нода `gpioleds` чужая (green/red Radxa на AO-банке,
`GPIOAO_2`/`GPIOAO_4`) и задизейблена — драйвер не пробится,
пин висит в воздухе.

Фикс `dtbo` (модуль [x96s_patcher/led_data.py](../x96s_patcher/led_data.py)):
фрагмент `5` с нодой `leds`/`sys_led` 1:1 со стоком (контроллер —
базовый periphs-банк `0x15` обоих LOS-DTB, TV и TAB проверены).
Имя `leds` — чтобы не мержиться с задизейбленным `gpioleds` донора.
Phandle во фрагменте нет вообще (квирк +0x100 загрузчика не касается),
ссылка `gpios = <0x15 …>` проходит буквально. Идемпотентность —
по каждой ноде отдельно (старый IR-only образ допатчится только LED).

Проверено: юнит (fresh / IR-only / реран no-op, dtc-кроссчек) + все 4
артефакта пересобраны из оригиналов на VM (`testzip` OK;
версии без LED — см. историю в git). Живьём после
прошивки: синий яркий, `/sys/class/leds/sys_led` на месте.
Бонус: `led_blink` из IR-оверлея теперь имеет шанс мигать диодом
при нажатиях пульта (в стоке этим рулит `meson-remote`).

## Красный: standby-диод, из Linux его нет

Красного нет ни в стоковом DT, ни в LOS, ни за одним драйвером ядра
(`led_sys`, `leds_state`, `gpio-leds` проверены по исходникам;
`sysled`/`state-led` нод в обоих DTB нет).

Живой перебор всех свободных GPIO (`/sys/class/gpio`, export;
занятые скипаются сами по `EBUSY`): карта чипов —
`periphs-banks base=410 ngpio=86`, `aobus-banks base=496 ngpio=16`
(наш синий — 474, т.е. base+64, среди занятых — сходится).
Держали каждый свободный пин HIGH 3 с + LOW 3 с (обе полярности,
активный ноль так тоже ловится) — красный не зажёгся ни разу.
Скрипт был одноразовый (в репо не ехал), суть цикла:

```sh
# adb root; adb shell
cd /sys/class/gpio
for chip in gpiochip*; do base=$(cat $chip/base); n=$(cat $chip/ngpio)
  i=0; while [ "$i" -lt "$n" ]; do N=$((base+i))
    if echo "$N" > export 2>/dev/null; then
      echo high > gpio$N/direction; sleep 3
      echo 0 > gpio$N/value; sleep 3
      echo "$N" > unexport
    fi; i=$((i+1)); done; done
```

Зато `echo mem > /sys/power/state` (suspend-to-RAM) зажигает его
стабильно: в первый раз сон длился ~0.5 с — будил CEC
(`wakeup_reason:0x3` от aocec при ОТКЛЮЧЁННОМ HDMI: висящий
в воздухе пин ловит шум). Для чистого эксперимента погасить все
`power/wakeup` в `/sys/devices` — сон держится, красный горит
постоянно. Будит штатно кнопка питания пульта (ИК-побудка идёт
мимо линуксовых флагов, уровень загрузчика/AOCPU). Вывод: standby-цепь,
отдельной ручки из андроида нет и не будет — включается только сном.

Осторожно: пин 511 (AO-банк, +15 от base 496) — похоже power-hold
платы: `high` переживает, прижатие к земле роняет питание. Не трогать.
